**ARGOS Defense 0.3.1: corrective release. Experimental detection; real-world accuracy not measured.**

ARGOS Defense is an experimental defensive investigation framework for analyzing supplied telemetry, identifying suspicious behavior, and assessing automation and LLM involvement with explicit evidence and uncertainty. It is now developed in the open: see [CONTRIBUTING.md](https://github.com/CSTHUESP/argos-defense/blob/main/CONTRIBUTING.md) and the [roadmap](https://github.com/CSTHUESP/argos-defense/blob/main/ROADMAP.md).

This release fixes nine residual issues found after 0.3.0 (R01–R09, docs/V031_REMEDIATION.md):
- Secrets inside lists, nested objects, CSV columns and case metadata are now redacted in every output; evidence that cannot be redacted safely is withheld, not mislabelled.
- Backups fail or are explicitly marked INCOMPLETE when referenced evidence is missing; restores rebase and verify every evidence reference.
- The directory watcher no longer confuses files that share a first line, and never consumes data that was not durably imported.
- LLM tool-call correlation keys are unambiguous and namespaced by a declared collector or the input file.
- Baselines and absence conclusions require declared coverage of the relevant event family.
- Attribution evaluation is now independent and alert-level.
- A test that could pass without calling the explainer was fixed.
- Analyses are admitted through a global FIFO queue, with one server per data directory.
- The release preflight authenticates Git reads for private repositories.

Follow-up fixes (FU1–FU5):
- Error responses are redacted.
- An interrupted import is resumed, never treated as complete.
- Watcher results no longer depend on chunk boundaries.
- A failed job can no longer block the analysis queue.
- Attribution evaluation now scores exact source records (eval-v2.2).
- An import is reported complete only after its revision is active (one atomic finalization step).
- Watcher recovery after a lost checkpoint re-delivers exactly the committed byte range, even if the file grew meanwhile.

### Upgrading
- Schema v4 also adds `inputs.delivery_key` (watcher delivery identity). Imports left `processing` by a crash, or whose finalization never completed, are marked `interrupted` at startup and are resumed on retry (`inputs.finalized` is added and existing rows are classified automatically).
- Start the new version on your data directory. The database migrates to schema v4 after a verified `argos.v3-backup.sqlite3`.
- Watcher checkpoints from 0.3.0 are re-identified conservatively.
- Coverage you declared without event kinds now covers only the event kinds present in that input; declare `--coverage-kinds` where an export is complete for more.
- Session/tool-call chains split across files need the same `--collector-id`.
- Only one server per data directory.

### Evaluation (synthetic only)
eval-v2.2 reserved set, 535 units, evaluated once after freezing:
- 110/320 benign units with a low-or-higher alert.
- Most attack scenarios 20/20; spray 18/20; source rotation interleaved with the real user 0/20 (known gap).
- 0 LLM overclaims in 714 alerts, scored against exact source records; 96/96 labelled chains directly observed.
- The earlier eval-v2.1 figures came from a scorer that accepted mismatched chains; that data is now reused development data.

Rules and data were written by the same project; this is not real-world validation.

### Capacity
- 300,000 events (stress profile) analysed in 69 s with a 2.8 GiB peak on 2 vCPU / 7 GiB.
- Default: 1 concurrent analysis, 8 queued.
- Larger cases are refused.

### Not included / not verified
- Binary EVTX: blocked (no installable parser in the build environment, and no genuine Sysmon EVTX sample).
- PCAP, live connectors, automatic containment and universal human-vs-LLM classification are out of scope.
- Not verified: real Ollama, Splunk/Sigma backends, desktop Windows/macOS sessions. The private-repository Git-read path of the release preflight (R09) is tested statically only, because the project is public.
